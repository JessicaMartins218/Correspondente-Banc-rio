# Story: Tratamento de Recusa/Pendência de Averbação com Alerta ao Operador e ao Cliente

## Context
Se a Dataprev ou o órgão pagador recusar a averbação (por margem excedida, benefício bloqueado ou divergência cadastral), o sistema deve identificar o motivo exato, orientar o cliente de forma empática e transparente no WhatsApp e gerar um chamado de alta prioridade para o operador da JM Consultoria tratar a pendência.

## Sources of truth (Shuri reads before coding)
- `.wize/planning/prd.md` (AC-05-2).
- Tabela de códigos de motivo de recusa/pendência de averbação (Dataprev / Bancos).

## Acceptance criteria
- **AC-05-2:** Dado que a averbação é recusada pelo órgão (por exemplo, por margem insuficiente ou benefício bloqueado para empréstimo), quando o webhook bancário devolve o motivo da recusa, então o sistema registra o log, envia mensagem esclarecedora ao cliente com a orientação de regularização e encaminha o caso com alerta de alta prioridade para o operador da JM Consultoria.

## Restrictions
- **Protected behaviors:** Não deixar o cliente sem retorno; mensagem deve explicar com linguagem simples (evitar jargões técnicos ininteligíveis).

## Notes for Shuri (Dev)
- Mapear dicionário de erros comuns (ex: código "04 - Benefício Bloqueado para Empréstimo" -> instrução de desbloqueio via app Meu INSS).
- Criar evento `proposal.averbation_failed` notificando o dashboard da JM Consultoria.

## Validation contract
- **AC → test:** Teste recebendo webhook com erro de margem e disparando notificação explicativa no WhatsApp + alerta para a mesa de crédito.

## Notes for Hawkeye (TEA)
- Validar se a mensagem enviada ao cliente não contém dados confidenciais de terceiros ou termos incompreensíveis.

## Done means
O cliente é orientado sobre como regularizar a pendência e a equipe humana da JM Consultoria recebe o caso imediatamente no painel.
