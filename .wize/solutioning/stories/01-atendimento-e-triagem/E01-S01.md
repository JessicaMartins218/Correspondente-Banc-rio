# Story: Recepção do Webhook do WhatsApp e Mensagem de Boas-Vindas com Consentimento LGPD

## Context
É o primeiro ponto de contato do cliente com o Correspondente Bancário. O cliente envia uma mensagem inicial para o WhatsApp da JM Consultoria. O sistema deve acolher o usuário, apresentar a marca e obter o consentimento obrigatório para tratamento de dados antes de colher qualquer informação pessoal.

## Sources of truth (Shuri reads before coding)
- `AGENTS.md` + `.wize/config/project.toml`.
- `.wize/planning/prd.md` (AC-01-1 e AC-01-2).
- Diretrizes da LGPD (Lei nº 13.709/2018) para consentimento explícito.
- Documentação da Meta WhatsApp Business Cloud API (Messages & Webhooks).

## Acceptance criteria
- **AC-01-1:** Dado que um novo usuário envia qualquer mensagem para o número oficial do WhatsApp, quando o sistema processa o webhook de entrada em menos de 1,5s, então responde com mensagem de boas-vindas da JM Consultoria e solicita o consentimento de tratamento de dados conforme a LGPD com botões "Concordo e Continuar" e "Saber Mais".
- **AC-01-2:** Dado que o usuário clica em "Concordo e Continuar", quando a confirmação é registrada, então o sistema armazena a data/hora, número de WhatsApp e IP/identificador do consentimento e solicita o CPF do cliente para consulta de triagem.

## Restrictions
- **Out of scope:** Coleta de dados bancários ou simulação nesta etapa.
- **Protected behaviors:** Respeitar a janela de atendimento de 24h da Meta; não reenviar termo se o usuário já consentiu nas últimas 24h em sessão ativa.
- **Compatibility:** Processamento idempotente de webhooks (`message_id` único para evitar mensagens duplicadas).
- **Security:** Registro imutável de auditoria do consentimento LGPD com timestamp UTC e hash do termo aceito.

## Notes for Shuri (Dev)
- Criar endpoint `POST /webhooks/whatsapp` com validação de assinatura `X-Hub-Signature-256`.
- Implementar fila/job assíncrono para despacho de respostas em tempo de resposta ≤ 1.5s.
- Utilizar formato de mensagem interativa do WhatsApp (`type: interactive`, `action.buttons`).

## Validation contract
- **AC → test:** AC-01-1 → Teste de integração do webhook com mock da Meta API; AC-01-2 → Teste unitário do serviço de persistência de consentimento LGPD.
- **Required checks:** Validação de payload da Meta, tratamento de retentativas HTTP 200 imediatas, checagem de timeout.
- **States:** Carregamento, mensagem enviada com sucesso, falha de envio com fallback.

## Notes for Hawkeye (TEA)
- Testes necessários: 2 unitários (validador de payload e formatador de mensagem), 1 de integração (webhook -> fila -> resposta WhatsApp).
- Mocks: Meta Graph API simulada via mock HTTP.
- NFR: Latência do webhook de ponta a ponta ≤ 1,5s.

## Done means
